# Public / Private Boundary

This repository is intentionally the smallest useful proof surface.

## Public kernel

- event and policy contracts
- strict validation and sensitive-data rejection
- exact/estimated/unknown separation
- receipt identity fields
- cache evidence rules
- retry lineage and duplicate-work checks
- operation budgets and route allowlists
- quality-gated unit economics
- deterministic reports and manifests
- synthetic examples and adversarial tests

## Private production layer

- prompts, scripts, story rules, quality corpora, and creative policy
- customer, channel, account, and provider-routing data
- credentials, browser sessions, cookies, OAuth refresh flows
- provider-specific retry and rate-limit behavior
- upload, publishing, scheduling, and revenue attribution
- production queues, workers, dashboards, and alert destinations
- signed raw receipts and proprietary benchmark datasets
- service pricing, support operations, and enterprise deployment

## Why this boundary matters

The public layer proves engineering discipline without giving away the operating system that creates differentiated media outcomes. It also lets adopters inspect the claim logic while keeping their own production data and provider integrations private.

## Non-goals

The kernel is not a hosted FinOps platform, a video generator, a creative judge, or a replacement for provider billing. It is an auditable reducer over sanitized evidence.
